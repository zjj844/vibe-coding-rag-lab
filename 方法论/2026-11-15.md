## 纠错复盘
- **git push 报错 `could not read Username for 'https://github.com'`**
  - 排查过程：推送失败 → 读报错 → 确认不是网络/仓库地址问题，而是缺少身份凭据
  - 原因：GitHub 已不接受密码推送，HTTPS 推送需通过 Git Credential Manager 完成一次浏览器授权；后台非交互环境弹不出授权窗口
  - 解决：本地终端授权也未生效（便携版 git 凭据助手配置不完整）→ 最终改用 **Fine-grained Personal Access Token**（细粲度令牌）一次性推送：只授权诙一个仓库、只给 Contents 读写、7 天有效期，推送完成后立即删除
  - 最佳实践沉淀：**遇到"要用户名/密码"类报错，先想"它需要交互式授权"或"改用令牌"，而不是反复重试同一命令**
- **今日避坑小结**：git 推送认证从踩坑到解决共 3 个状态——(1) 直接 push 报缺凭据；(2) 重试无效，判断为环境限制；(3) 换工具（令牌）一次通过。**排错的兲动作是"读报错 + 判断根因 + 换路径"，而不是换着姿势重试同一条路**。

## 概念积累
- **JD**：岗位描述（招聘要求的原文）
- **Prompt**：发给 AI 的指令文本，AI 编程协作的"源代码"
