# 2026-11-19 RAG 自动化测试：设计决策与踩坑

## 我要解决什么问题

RAG 系统的失败大多是**静默的**：答案读起来通顺，但引用的段落根本不支持它，人眼看不出来。
所以我要的不是"多写几个测试"，而是一套**能把"检索变好了没有"变成数字**的东西。

## 四个设计决策（及理由）

### 1. 测试分两轨：`tests/` 与 `evals/`

- `tests/`：布尔判定，必须全绿，进 CI，卡合并；
- `evals/`：统计指标，出报告，不卡 CI。

**理由**：LLM 应用的输出天然不确定。如果两类混在一起，测试会时红时绿，人第一反应是 `skip` 掉，
最后没人信测试。分轨之后，**确定性指标（引用合法率）当硬门禁，统计指标（Recall@5）设下限并留波动空间**。

### 2. 一组数据两处用

同一份 `gold_set.jsonl` 既驱动 pytest 断言，也驱动 `EVAL.md` 的指标表。

**理由**：标注成本是这类项目最贵的投入。分成两份就必然标注两遍，而且两份会逐渐不一致。

### 3. 嵌入器 / 向量库 / LLM 全部做成可注入对象

`RagPipeline(embedder=..., llm=...)`；向量库只要求实现 `add` / `search`。

**理由**：可测试性来自"边界清楚"。另一个反面是：如果为了测试去 mock 掉检索器，那等于把被测对象挖掉了，测了个空。

### 4. CI 里用一个"假模型"（抽取式）

`ExtractiveLLM` 从命中块里抽最相关的一句当答案。

**理由**：测试要测的是**链路**（检索 → 编号 → 引用 → 拒答），不是模型智商。真实模型进 CI 只会带来波动和账单。
真实模型留给人工评估（`DeepSeekLLM` 已写好，注入即可）。

## 三个踩坑（比代码值钱）

### 坑 1：阈值靠拍脑袋 → 误拒答

第一版把"支持度阈值"设成 0.22，结果 **q07/q11 这两条语料内的问题被误拒答**。
诊断办法：把每条用例的 support 打出来看分布——

```
语料内问题：0.111 ~ 0.647
语料外问题：0.000 ~ 0.059（除一个例外，见坑 3）
```

取 0.09（留安全边际），误拒答消失。

**教训**：阈值不是拍出来的，是**测出来的分布**里挑出来的。而且换语料必须重测。

### 坑 2：测试假绿（两次！）

为验证测试本身有效，做了**变异测试**：故意把 `overlap` 逻辑改坏，看测试能不能抓到。

| 轮次 | 测试数据 | 注入 bug 后 | 结论 |
|---|---|---|---|
| 1 | `"甲乙丙丁…" * 12` | 仍全绿 | 重复数据让尾部片段碰巧出现在下一块 |
| 2 | 每句相同后缀"用来验证重叠。" | 仍全绿 | 共同后缀让断言恒成立 |
| 3 | 每句唯一标记 `句子编号i的唯一标记为M{i}Z。` | **2 条报红** | 真绿 |

**教训**：**测试通过 ≠ 测试有效。** 测试数据必须互不重复、后缀唯一。
判定测试有没有效的方法只有一个——**把代码改坏，看它变不变红**。

### 坑 3：词面重合 0.75，却完全无法回答

问题 `Python 3.13 上 torch 安装包有多大`：

- 检索**正确命中**了关于 torch 安装的文档；
- 词面支持度 0.750（全语料最高）；
- 但文档里**没有"安装包大小"这个信息**，抽取式生成器照样硬答。

**根因**：词面重合 ≠ 可回答性。这是方法论缺陷，不是代码 bug（换语义嵌入或判官模型才能解）。

**处理方式**：登记为 known issue（gold set 的 notes 标"预期失败"），严格口径排除、全量口径照实报 0.667。
**不掩盖、不删用例**——删掉它，指标就好看了，但问题还在。

## 数据（可复现）

`scripts/tune.py` 扫 chunk_size × overlap：

| chunk_size | overlap | 块数 | Recall@5 | 证据命中率 |
|---|---|---|---|---|
| 200 | 0 | 18 | 0.889 | 1.000 |
| 200 | 40 | 20 | **1.000** | 1.000 |
| 120 | 0 | 32 | 0.889 | 0.778 |
| 120 | 40 | 35 | 0.889 | 0.889 |

**结论**：
1. 同样 chunk_size，overlap 0→40 让 Recall@5 从 0.889 到 1.000 —— "overlap 防边界漏召回"被数据证实。
2. 块越小不等于越准：120 字时块数翻倍，证据命中率反而下降（关键证据被切碎）。
3. 400 字也能到 1.000，但那是"块大容易命中"，**精度没变好**——当前指标不测精度，是盲区。

## 前端：两个框架，一套 API（以及被网络逼出来的选型）

目标：一个后端，两套前端，验证"接口契约稳定，前端可替换"。

### 决策 1：后端拆成 service + 适配器

`api/service.py` 只定义业务与返回字段，`app_flask.py` / `app_fastapi.py` 是两个薄适配器。
好处：接口契约只写一次；前端和测试都对着 service 写；**换 Web 框架不动业务**。

### 决策 2：Vue 用本地化库，React 用 Vite 工程

本机**完全没有外网**（PyPI、jsdelivr、npmmirror 全部 SSL 断连），这直接决定了选型：

| | 方案 | 结果 |
|---|---|---|
| Vue | 从本机已有的 `vue.global.prod.js`（3.5.16）拷到 `web/vendor/` | ✅ 离线可跑、可验证 |
| React | 本机只有 `react` 的 UMD，**没有 react-dom 的浏览器构建**（React 19 已取消 UMD） | ⚠️ 只能给 Vite 工程源码，等有网 `npm install` |

**教训**：技术选型不只看"哪个更好"，更要看"当前环境能不能验证"。
一个**能跑给你看**的 Vue 版，比一个"理论上更好但跑不起来"的版本有价值得多。
同时把 FastAPI 适配器写成源码（未被本机验证），并**在文件头明确标注未验证**——不假装它跑过。

### 决策 3：库文件进仓库（`web/vendor/`）

代价是仓库多了 155KB，收益是**离线可复现**：任何人 clone 下来都能跑。
对"一键能跑"这条验收来说，这笔交易是划算的。

### 又一个被页面暴露的 bug

接口通了之后，前端显示的第一条答案是：

```
# 系统库缺失：libGL.so.1现象：跑 unstructured 的 partition_pdf，hi_res 策略直接崩溃…
```

**根因**：抽取式的句子切分只按中文句末标点切，没把换行算进去，
于是 Markdown 标题和下一句被粘成一句。修法：切句时加上 `\n`，并跳过以 `#` 开头的行。

**教训**：**CLI 里看着"能用"的东西，上了页面就露馅。**
接口测试全绿也发现不了这种问题——它属于"展示层质量"，必须有眼睛看一遍。

### 坑 4：改了分词，把上一小时的结论推翻了

这个坑最值得写，因为它是**真实发生的自我推翻**。

时间线：

1. 第一版 `grams()` 对纯 ASCII 也切字符 n-gram → `RAG` 变成 `ra`/`ag`/`g `；
2. 这些碎片**永远匹配不上中文语料**，却占着支持度公式的分母；
3. 后果：两条语料内问题（q03、q11）被误拒答（支持度只剩 0.037）；
4. 我先改了句子切分（加换行、跳过 `#` 标题），结果 **q11 从误答变成误拒**——修一处，坏一处；
5. 继续追，才定位到真正的根因是分词噪声；修掉后 q03/q11 都恢复；
6. 然后**重新跑参数实验**，发现之前那条"overlap 让 Recall@5 从 0.889 到 1.000"的结论**消失了**——
   它本来就是噪声制造出来的假差异。

**三条教训**：

- **指标变化必须归因**：数字变了，是策略改好了，还是 bug 修掉了？含义完全相反。
- **改动底层（分词/解析/嵌入）后必须全量重跑实验**，否则会拿着旧结论写博客。
- **发现自己写过的结论被推翻时，保留原文 + 加更正记录**。偷偷改掉是最差的选择，因为下次你还会犯同样的错。

### 坑 5：真模型一上来就把我的三条假设全打穿了

接通 DeepSeek 后跑同一份 gold set，结果和假模型完全不一样——这才是"换真实组件"最大的价值。

**被推翻的假设 1：重复引用编号是非法。**
真模型常写 `[1] … [1]`（同一份资料支撑两句话）。我的校验规则禁止重复，
于是引用合法率从 1.000 掉到 **0.3333**，7 条用例被判非法。
那条规则唯一的作用是适配"假模型只输出一个 `[1]`"——**它是为假模型量身定做的假规则**。

**被推翻的假设 2：我的测试是对的。**
`test_validate_detects_duplicate_citation` 断言"重复=非法"。
错误假设被写进测试后，就一直绿灯通过。**测试为 bug 背书**，比没有测试更危险。

**被推翻的假设 3：q10 是"任务不可能"。**
我把"资料里没有大小信息却硬答"登记成"方法论缺陷"，说只能换语义嵌入才能解。
真模型接手后，q10 **正确地拒答了** → 说明它不是任务天花板，只是抽取式实现的局限。
**登记缺陷时必须写清"是实现限制还是任务不可能"**，否则你会误以为无解而放弃。

**顺带学到的两件事：**

- **模型名别照抄文档**：该 key 可用 `deepseek-flash` / `deepseek-v4-pro`，文档里的 `deepseek-chat` 会 400。
- **网络抖动是常态**：通过代理调用会偶发 `SSL: UNEXPECTED_EOF` 和 `307 Temporary Redirect`。
  12 条用例的评估里挂 1 条就整份作废，所以必须内置重试：4xx 立刻失败（重试没意义）、
  3xx 跟随 Location、网络类错误指数退避 3 次。

### 坑 6：环境本身也在给你出题

这一轮踩的环境坑（都是真实报错）：

| 现象 | 根因 | 解法 |
|---|---|---|
| `invoke-webrequest` / pip 全部 SSL 断连 | 直连被断，但系统代理开着（Clash 7877） | 显式 `HTTP_PROXY` / `HTTPS_PROXY` |
| `setx` 设的 key 读不到 | 进程比变量启动得早 | 代码里查注册表 `HKCU\Environment` 兜底 |
| `npm install` EPERM 于 `npm-cache` | 缓存目录不可写 | `--cache` 指到工作区 |
| `npm install` EPERM 于 `spawn` | esbuild 的 postinstall 要派生子进程 | `--ignore-scripts`，然后用 esbuild 二进制直接打包 |
| pytest `tmp_path` PermissionError | 系统临时目录不可写 | 测试改用工作区内临时目录 |

**教训**：环境问题的共同点是"**报错信息不指向真正原因**"。
所以我把诊断做成了一条命令：`python scripts/check_env.py`，
一次性告诉你 key、代理、网络、依赖各自的状态，而不是让你逐个猜。

### 坑 7：React 页面黑屏——测试全绿，页面全黑

**现象**：`/vue/` 正常，`/react/` 点进去一片黑（只有深色背景，没有任何 UI）。

**排查路径**（这次没瞎猜，按顺序排除）：

1. 资源是否到位 → 写 `scripts/verify_web.py` 逐条检查：HTML、app.js、app.css 全部 200 且体积正常 ✅
2. 是 CSS 没加载还是 JS 没跑 → 背景是深色（来自 app.css）→ 说明 **CSS 加载了、JS 没跑起来**
3. 产物格式对不对 → 确认是 IIFE、无 `import.meta`、无 `process` 残留 ✅
4. **把组件树拿到 Node 里渲染**（`react-dom/server`）→ 立刻拿到真报错：
   ```
   ReferenceError: React is not defined at App
   ```

**根因**：esbuild 默认用**经典 JSX 转换**（生成 `React.createElement`），
但我的组件是按 React 17+ 的**自动运行时**写的（文件里没有 `import React`，Vite 默认就这么编译）。
于是产出的 bundle 一执行就抛错 → 整页白/黑。

**修法**：加 `--jsx=automatic`。顺带把产能从 465KB 降到 150KB（production React），
因为 `--define:process.env.NODE_ENV="production"` 的引号被 cmd 吃掉了，
esbuild 定义成了"标识符 production"而不是字符串。

**四条教训：**

1. **接口测试全绿 ≠ 页面能用。** 这一层根本没有测试覆盖 —— 它属于"浏览器里才暴露"的问题。
2. **黑屏先分两半**：CSS 有没有生效（背景色是最快的判据）→ 生效则是 JS 的问题。
3. **能在 Node 里渲染就在 Node 里渲染**（`react-dom/server` + 冒烟入口），
   比在浏览器里靠肉眼和 console 猜快十倍。
4. **给页面加错误浮层**：`window.onerror` + `unhandledrejection` 直接把错误画在页面上。
   黑屏是最难查的形态，把它变成"红字报错"能让下次排查从半小时变半分钟。
